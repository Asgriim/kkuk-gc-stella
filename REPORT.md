## Сборка и запуск

Реализация на C++20, runtime собирается как C11.
Проверено на Ubuntu 26.04.1 LTS с ядром `7.0.0-44-generic`,
GCC 15.2.0, Make 4.4.1, CMake 4.2.3 и Python 3.14.4.
Нужны CMake от 3.20 и Python от 3.10. В Ubuntu инструменты устанавливаются
через `sudo apt install build-essential cmake python3`.

Через Make можно собрать проект и запустить оба набора тестов

```sh
make -j4
./build/chat 10 4096
make test -j4
make test-stella -j4
```

`make test` запускает 170 тестов ABI, `make test-stella` запускает 5 тестов Stella.
Последний аргумент программы задаёт лимит памяти в байтах.
Сборщик находится в `build/libstella_gc.a`. Файл
[stella_abi.hpp](internal/stella_abi.hpp) подключает заголовки C через `extern "C"`.
При ручной линковке через `cc` к библиотеке нужно добавить `-lstdc++`.

Те же тесты можно запустить через CMake

```sh
cmake -S . -B cmake-build-debug -DCMAKE_BUILD_TYPE=Debug -DGC_ENABLE_STELLA_TESTS=ON
cmake --build cmake-build-debug -j4
ctest --test-dir cmake-build-debug --output-on-failure
```

Для компиляции тестов Stella используется Docker-образ из задания.
Для их запуска нужен работающий Docker.
Без `GC_ENABLE_STELLA_TESTS=ON` собираются только тесты ABI.
`BUILD_TESTING=OFF` отключает тесты.
Для выбора одного случая или группы

```sh
ctest --test-dir cmake-build-debug -R '^generations/barrier$' --output-on-failure
ctest --test-dir cmake-build-debug -L stella --output-on-failure
python3 tests/run_tests.py --bin-dir build --filter 'generations/barrier'
```

## Алгоритм и устройство реализации

Реализована копирующая сборка по алгоритму Чени со сборкой по поколениям.
Поколений два, порог старения равен 1.
Код находится в [gc.cpp](gc.cpp). Сборка запускается только из `alloc`.

`collectYoung` выполняет малую сборку. Достижимые молодые объекты переходят
в старшее поколение. Обход начинается с корневых переменных и полей старших
объектов, учтённых в множестве запомненных указателей `remembered_`.
Далее сканируются перенесённые объекты.
`collectFull` выполняет полную сборку обоих поколений от корней.
Объекты копируются в резервную область, которая становится старшим поколением.

Основные инварианты следующие.

- `forward` сохраняет перенаправляющий указатель в `gc_word` до сканирования полей.
  Поэтому общие ссылки и циклы сохраняют единственную копию
- В `scanCopies` область `[scan, used_)` является очередью Чени.
  До `scan` находятся уже просканированные объекты
- Инвариант границы поколений требует учесть каждое поле из старшего поколения
  в молодое. `writeBarrier` добавляет содержащий его объект в `remembered_`
- Крупные объекты с управляемыми полями запоминаются сразу при выделении,
  потому что первоначальное заполнение не вызывает барьер

Сборщик обновляет адреса объектов в корневых переменных.
Примитивные поля сохраняются, статические объекты не меняются.
У копии заново вычисляется `fields`, неактивные слоты обнуляются.
`updateObject` обновляет тот же объект и меняет дескриптор последним.
Исключения C++ перехватываются в `callAbi` на границе интерфейса C.

## Параметры

`max_heap_bytes` задаётся через `StellaGcConfig` и должен быть положительным.
Он ограничивает сумму размеров объектов, которые ещё не освобождены.
Служебная память, свободный резерв и временные копии не учитываются.

`STELLA_GC_YOUNG_BYTES` задаёт размер молодого поколения в байтах.
Допустимы целые десятичные числа от 1 до `max_heap_bytes` без знака и пробелов.
По умолчанию используется `max(1, max_heap_bytes / 4)`.
Ошибочные значения отвергаются.

Старшее поколение и резервная область имеют размер по `max_heap_bytes`.
Объект, который больше молодого поколения, сразу выделяется в старшем.
Нехватка места вызывает малую или полную сборку, а если запрос всё равно
не помещается, вызывается `stella_gc_out_of_memory`.

## Статистика и состояние

```sh
STELLA_GC_YOUNG_BYTES=1024 STELLA_GC_STATS=1 STELLA_GC_STATE=1 ./build/chat 10 4096
```

Пример статистики

```text
requested bytes: 7080
rounded bytes: 7080
allocated objects: 210
collections: 7
minor collections: 6
full collections: 1
occupied bytes: 3688
maximum occupied bytes: 4072
```

Полный набор счётчиков находится в [gc_stats.hpp](internal/gc_stats.hpp).
Размеры заданы в байтах. Печатаются выделения, сборки, текущая и максимальная
занятость всей кучи и поколений, обращения к полям, срабатывания барьеров
и текущая и максимальная глубина стека корней, число постоянных корней.
Копирование не считается выделением. Инициализация и внутренние обращения
не входят в счётчики доступа. Обновление добавляет число новых активных полей.
Максимумы занятости фиксируются в конце `alloc`. Срабатывание барьера
учитывается при добавлении объекта в множество запомненных указателей.

Пример состояния

```text
generational Cheney: occupied=3688 free=408 limit=4096 promotion_age=1
collection=idle scan=inactive
```

Далее выводятся области с границами, размером, занятостью, свободным местом,
`next` и `limit`, объекты со всеми полями и `gc_word`, множество запомненных указателей
и адреса корневых переменных с их значениями. `used` включает выравнивание,
`occupied` содержит размеры объектов. Активного `scan` между вызовами нет,
поскольку сборка синхронная. Печать сборку не вызывает.

## Тестирование

В [tests](tests) находятся 170 запусков ABI и 5 запусков Stella.
Тесты интерфейса находятся в `tests/abi/`, программы Stella в `tests/stella/src/`.
Файлы `tests/stella/params/*.json` задают аргументы, лимиты памяти,
ожидаемый ответ и проверки статистики.
Каждый случай запускается отдельно. Для ошибочного вызова ожидаются код 1
и сообщение runtime. Падение или зависание считается ошибкой теста.

- `graph` проверяет циклы и общие ссылки после сборки
- `barrier` проверяет ссылку из старшего поколения в молодое после малой сборки
- `update` проверяет смену формата, сохранение ссылок на обновлённый объект и обнуление неактивных слотов
- `half_heap` проверяет 250 списков при достижимом графе не больше половины лимита
- `retained_chain` на Stella возвращает 56 для аргумента 28, поскольку каждый шаг добавляет два узла

Тесты ABI запускаются с лимитами 2048 и 4096 байт и разными размерами
молодого поколения. 

```sh
cmake -S . -B cmake-build-asan -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DGC_ENABLE_STELLA_TESTS=ON -DGC_ENABLE_SANITIZERS=ON \
  -DCMAKE_C_FLAGS=-fno-pie -DCMAKE_CXX_FLAGS=-fno-pie \
  -DCMAKE_EXE_LINKER_FLAGS=-no-pie
cmake --build cmake-build-asan -j4
UBSAN_OPTIONS=halt_on_error=1 \
  ctest --test-dir cmake-build-asan --output-on-failure
```

После копирования `fields` указывал на старый
объект, поэтому упал тест `layouts`. Исправил пересчётом `fields` в `forward`.

## Известные ограничения

Порог старения фиксирован и равен 1. После первой малой сборки, которую объект
пережил, он переходит в старшее поколение. Настройку порога не делал,
поскольку она относится к расширенной части.

Лимит кучи учитывает только объекты. Вместе с резервом и служебными структурами
процесс может занимать больше памяти.
